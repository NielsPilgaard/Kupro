Import: ten directions

Ten clickable mockups of the import experience from task 023 and ADR-019, made before any React code so we can pick a direction. Each one is a different idea, not another screen of the same design. Every file walks the whole flow: pick a source and connect, choose scope, map types, states and people, decide the hierarchy, read the dry-run plan, then watch the import and its result. Built on the Kobber tokens from the design guide, light by default (dark via the bar at the top of each page), keyboard reachable.

The hierarchy is a team choice

Azure DevOps has four levels and Kupro has three. Every direction with a mapping step shows the fold as two equal options with their own counts, never as a buried default:

  • Keep Epics: Epic → Epic, Feature → Feature, User Story → Task, ADO Task → Task under the Feature with a relates link to its old Story. 29 Epics · 195 Features · 8,783 Tasks, 5,362 re-parented, no labels.
  • Fold Epics: Epic → label, Feature → Epic, User Story → Feature, Task → Task. 195 Epics · 2,650 Features · 6,133 Tasks, 63 re-parented, 29 labels.

Jira Initiatives get the same choice (a label on their Epics, or Initiative → Epic and Epic → Feature). It appears where Jira does: 08 (a finished Jira import), 09 (switch the source to Jira) and 10 (the Jira tab).

Combinations worth considering

  • 09 for setup, 08 for life after run 1. One screen gets most teams to their first run; the dashboard handles the weeks of delta syncs, conflicts, invites and Finish that follow.
  • 03's live plan with 07's trees inside the hierarchy step. The fold is the decision people get wrong; seeing their own work items move is the best explanation.
  • 04's diff as the run report in any direction: run 2 and later read naturally as "4 created, 38 updated, 2 conflicts".
  • 06's CLI commands under every web step, like the command palette footer does, keeps parity visible.
