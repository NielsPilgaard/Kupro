# ADR-011: Internationalization — English First, Danish at Launch

## TL;DR

- All UI strings via i18n keys from day 1 (e.g. `react-i18next` or `i18next` + ICU).
- `en` source, `da` required before launch. Dates/numbers via `Intl`, user locale + timezone stored on profile.
- API returns stable error codes; client localizes. CLI/MCP are English.

## Status

**Accepted**

## Context

Danish audience, international ambition. Retrofitting i18n later is expensive.

## Consequences

### Positive

- **POS-001**: Cheap now, expensive later — done once.

### Negative

- **NEG-001**: Slight friction writing UI (keys instead of literals). CI check for missing `da` keys.
