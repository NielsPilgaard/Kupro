# ADR-004: Hosting — OVHcloud VPS, Dokploy, Docker Compose

## TL;DR

- One OVHcloud VPS, **≥ 8 GB RAM** (Keycloak alone ~1 GB, observability ~1 GB steady), EU region closest to DK (e.g. Limburg/Frankfurt or Gravelines). Dokploy as deploy/PaaS layer.
- Compose stack: `api`, `web` (static SPA via nginx, Traefik ingress from Dokploy), `postgres`, `keycloak`, plus the observability stack ([ADR-014](ADR-014-observability.md)) — generated by `aspire publish` ([ADR-012](ADR-012-aspire.md)).
- Self-managed PostgreSQL. Backups: the backup agent, to OVHcloud Object Storage, restore drilled weekly ([ADR-016](ADR-016-postgres-backups.md)).
- Attachments/images in OVHcloud Object Storage.
- CI: GitHub Actions builds images → registry → Dokploy deploy webhook.

## Status

**Accepted**

## Context

EU-only infra ([ADR-006](ADR-006-eu-vendor-policy.md)), bootstrapped budget, solo operator. Compose keeps prod close to
dev and doubles as the future self-hosting package.

## Decision

As above. Postgres and API on the same host for lowest latency.

## Consequences

### Positive

- **POS-001**: Cheap, simple, French vendor (EU jurisdiction).
- **POS-002**: Dev/prod parity; self-host path almost free.

### Negative

- **NEG-001**: We own DB ops: backups, upgrades, monitoring. Single VPS = single point of failure.
- **NEG-002**: Vertical scaling only until we split DB to its own VPS.

## Alternatives Considered

### Scaleway with managed Postgres

- **ALT-001**: **Rejection Reason**: Owner preference for OVHcloud + Dokploy; managed DB cost not justified yet.

## Implementation Notes

- **IMP-001**: Registry: verify EU option (OVHcloud Managed Private Registry) vs. GHCR (GitHub is allowed per ADR-006).
- **IMP-002**: Observability: see [ADR-014](ADR-014-observability.md).
- **IMP-003**: Restore drill documented in `docs/runbooks/` before first external user: [restore runbook](../runbooks/restore.md), [ADR-016](ADR-016-postgres-backups.md).
