# AGENTS.md

Instructions for AI coding agents working on this repository.

## Project Overview

**Flowstate** — Danish, EU-sovereign, agent-first issue tracker and planner. Product intent: [docs/product.md](docs/product.md).
All technical decisions: [docs/adr/INDEX.md](docs/adr/INDEX.md). Work is specified in numbered `tasks/*.md`; priority and build order: [tasks/INDEX.md](tasks/INDEX.md).
UI rules: [docs/design-guide.md](docs/design-guide.md); brand, voice, EN/DA glossary: [docs/branding.md](docs/branding.md).

- **Backend**: .NET 10, ASP.NET Core plain controllers, EF Core + PostgreSQL ([ADR-002](docs/adr/ADR-002-backend-stack.md))
- **Frontend**: React + TS + Vite SPA, TanStack Query/Router ([ADR-003](docs/adr/ADR-003-frontend-stack.md))
- **Agent surfaces**: REST, CLI, MCP — always in parity ([ADR-001](docs/adr/ADR-001-agent-parity.md))
- **Auth**: Keycloak ([ADR-005](docs/adr/ADR-005-auth-keycloak.md)); **Hosting**: OVHcloud + Dokploy ([ADR-004](docs/adr/ADR-004-hosting.md))
- **Dev/deploy**: `aspire run` locally; `aspire publish` generates prod compose ([ADR-012](docs/adr/ADR-012-aspire.md))
- **Observability**: OTLP → self-hosted Grafana/Loki/Tempo/Prometheus; dashboards/alerts as code in `infrastructure/observability/` ([ADR-014](docs/adr/ADR-014-observability.md))

## Critical Rules

1. **Parity**: a new API operation needs a CLI command and an MCP tool (or an explicit opt-out). See ADR-001.
2. **Thin adapters**: controllers, MCP tools and CLI commands contain no business rules — feature services do.
3. **DbContext**: use `IDbContextFactory<FlowstateDbContext>` with `await using`; `AsNoTracking()` + projections for reads.
4. **Tenancy**: every tenant-owned entity has `WorkspaceId`; never bypass the global query filter without a comment explaining why. See ADR-009.
5. **Performance**: respect the latency budget ([ADR-010](docs/adr/ADR-010-performance-budget.md)) — paginate, index, no N+1.
6. **EU only**: no new vendor/SaaS without adding it to the register in [ADR-006](docs/adr/ADR-006-eu-vendor-policy.md).
7. **i18n**: no hardcoded UI strings ([ADR-011](docs/adr/ADR-011-i18n.md)).
8. **Design tokens**: no hex/rgb/font names in components — tokens from [design-guide.md](docs/design-guide.md) only.
9. **Minimal diffs**: don't reformat code you didn't change.
10. **Docs**: ADRs and tasks follow the progressive-disclosure convention (frontmatter `description`, TL;DR). Decisions live in ADRs only — link, don't restate.

## Security

- Never commit secrets; local secrets in `.env` (gitignored), production in Dokploy env.
- New production parameter, domain or manual step → update [docs/runbooks/deploy.md](docs/runbooks/deploy.md).
- Validate input at system boundaries. SignalR hubs require `[Authorize]`.
