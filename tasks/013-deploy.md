# Task 013: Production deploy on OVHcloud + Dokploy

See [ADR-004](../docs/adr/ADR-004-hosting.md). Compose file is generated by `aspire publish` ([ADR-012](../docs/adr/ADR-012-aspire.md)) — prod tweaks go in AppHost publish callbacks.

## Acceptance criteria

- [ ] Push to `main` deploys automatically, using `deploy/docker-compose.yaml` from `aspire publish`.
  In repo: CI → Staging (E2E on the published images) → CD, as in Skoleoverblikket; live once the
  [GitHub configuration](../docs/runbooks/deploy.md#github-configuration) is set.
- [ ] Nightly backup + WAL archiving verified; restore drill documented in `docs/runbooks/`.
  Approach: Skoleoverblikket's Postgres backup agent (`pg_receivewal` + pgBackRest, restore into an A/B volume).
  Not started: adopt it once it is proven there, and update ADR-004 then.
- [ ] Keycloak production setup: production realm settings, and Flowstate branding (design tokens, logo, EN/DA) on the
  login pages and in Keycloak's emails.
- [ ] Secrets only in Dokploy env, never in repo.
- [ ] Observability live: Grafana parameters set in Dokploy and its domain routed, a test alert email arrives, images stamped with the commit, PingPuffin checks `/api/v1/status` ([ADR-014](../docs/adr/ADR-014-observability.md), [infrastructure/observability](../infrastructure/observability/README.md)).
- [ ] [Deploy runbook](../docs/runbooks/deploy.md) followed end to end and its open gaps closed.
