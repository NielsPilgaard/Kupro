# Task 005: CLI

See [ADR-001](../../docs/adr/ADR-001-agent-parity.md).

## Scope

- Client generated from OpenAPI.
- `flowstate login` (device flow), `flowstate token set` (PAT).
- `issue list|get|create|update|move|comment`, `project list`, `sprint list`.
- Table output on TTY; JSON when piped or with `--json`.
- AOT publish for win-x64, linux-x64, osx-arm64 in CI.

## Acceptance criteria

- [x] An agent can create, update and close an issue using only the CLI.
- [ ] Binary cold start < 50 ms. Enforced by the `cli` CI job (linux-x64); not measured locally (no native linker on the dev box).

## Implementation notes

- Client: Kiota, generated at build from `openapi/flowstate.json` into `obj/` (needs `dotnet tool restore`).
- Every API-backed command is an `ApiCommand` carrying its operation ids; `Cli.CoveredOperations()` feeds the parity
  test (task 006). `issue comment` arrives with task 008 and `sprint list` with task 010.
- Auth: `flowstate login` runs the device flow against the authority advertised by `GET /api/v1/status`;
  `flowstate token set` or `FLOWSTATE_TOKEN` uses an API token. Config lives in `%APPDATA%/flowstate/config.json`
  (`~/.config/flowstate` on Linux/macOS, mode 600); `FLOWSTATE_URL`, `FLOWSTATE_WORKSPACE`, `FLOWSTATE_CONFIG` override.
- Every mutation sends a fresh `Idempotency-Key` (reused by Kiota's retry handler) and `X-Flowstate-Client: cli`.
- Output: tables on a TTY, JSON when piped or with `--json`; API errors print the stable code and exit 1.
- Verified live: device login through Keycloak, then workspace/project/epic/feature/task/labels/relation/close.
