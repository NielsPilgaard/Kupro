# Task 006: MCP server

See [ADR-001](../../docs/adr/ADR-001-agent-parity.md), [ADR-005](../../docs/adr/ADR-005-auth-keycloak.md).

## Scope

- Official C# MCP SDK; tools call feature services directly.
- Coarse tool set (~12): `search_issues`, `get_issue`, `create_issues`, `update_issues`, `add_comment`, `list_projects`, `list_sprints`, `get_plan`, ...
- OAuth via Keycloak: DCR + experimental `resource-indicators,cimd` features ([ADR-005](../../docs/adr/ADR-005-auth-keycloak.md) IMP-001); fallback pre-registered client.
- Serve Protected Resource Metadata (`/.well-known/oauth-protected-resource`) from the API.
- `kupro mcp` stdio bridge using the CLI's token.
- Parity test: OpenAPI operations <-> CLI commands <-> MCP tools.

## Acceptance criteria

- [ ] Claude Code connects via remote URL and via `kupro mcp`, and can manage issues. Verified with the official MCP
  client (remote URL + agent token) and live through `kupro mcp` after a device login; the OAuth discovery chain
  (401 challenge, Protected Resource Metadata, anonymous DCR at Keycloak) answers correctly, but a full Claude Code
  OAuth sign-in has not been run yet.
- [x] Parity test fails when a new endpoint has no CLI/MCP surface.

## Implementation notes

- Tools (12): `get_me`, `list_workspaces`, `list_projects`, `create_project`, `list_members`, `list_labels`,
  `search_issues`, `get_issue`, `create_issues`, `update_issues`, `relate_issues`, `unrelate_issues`. `add_comment`,
  `list_sprints` and `get_plan` arrive with tasks 008, 010 and 011. Bulk create accepts `parent: "#0"` to point at an
  earlier issue in the same call, so an epic and its children go in one request.
- Stateless streamable HTTP at `/mcp`; tools enter the workspace through `McpWorkspace` (same membership and role rules
  as the REST filter, agents capped at Member, activity recorded "via MCP"). Errors return `isError` with the stable code.
- Every 401 carries `WWW-Authenticate: Bearer resource_metadata=...`; the API serves Protected Resource Metadata. Tokens
  are accepted with audience `kupro-api` or the MCP resource URL (`Api:PublicUrl` + `/mcp`, RFC 8707).
- Dev realm: anonymous DCR allowed from localhost (Trusted Hosts policy) and a pre-registered public `mcp` client with
  loopback redirects as fallback. The production realm is task 013.
- `kupro mcp` forwards stdio JSON-RPC to `/mcp` with the CLI's credentials (no MCP SDK in the CLI, stays AOT-small).
- Parity: `ParityTests` reads `/openapi/v1.json`, the CLI's `ApiCommand` tags and the tools' `[CoversOperations]`;
  endpoints opt out with `[NoAgentSurface(surface, reason)]`. It also fails on operations without a typed 2xx schema.
